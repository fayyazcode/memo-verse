# Mobile-first HUD redesign

The original HUD permanently displayed navigation, camera/build utilities, a companion status card and an expanded squad panel in separate overlapping layers. Mobile text was mostly 8–10px. This increment extends the existing React/Zustand interface and keeps the world, movement, combat, missions, inventory, crafting, collection and adventure save format.

## Implemented layout

- Menu opens a right-side navigation drawer for backpack, journal, collection, squad, commands, world map, settings, save/pause, camera selection and building. There is no permanent bottom navigation dock.
- Mobile exploration shows a compact player card, gold currency indicator, collapsible minimap and companion summary. The center remains available for the character and world.
- The companion summary or blue Ability button opens a right-hand ability tray beside the movement joystick. It contains squad switching and real ability buttons. Ready, cooldown, level-locked and insufficient-charge states have distinct labels/icons/borders. Desktop retains a compact hotkey bar.
- Thumb controls distinguish attack (red), interaction (green), companion (blue) and jump (neutral). Run remains beside the joystick. The six-slot hotbar is anchored to the bottom safe area.
- Building replaces combat controls with place/remove selection, camera rotation and exit. Placement still uses the existing world tapping/preview/validation; blocks are axis-aligned, so the rotation control explicitly turns the view rather than pretending to rotate block geometry.
- Tracked mission summary shows the current objective, its count, overall progress and approximate destination distance. Players can cycle active quests or track one in the journal. Tracking and UI scale persist as browser settings. A demolished shelter is projected as unfinished using the existing shelter rule.
- Full map filters toggle missions, NPCs, discoveries and known (collected) creature habitats. Compact minimap missions follow the tracked quest.
- Notifications use semantic severity, coalesce repeated resource amounts and preserve queued rewards/warnings ahead of routine messages. Only one toast is shown. Existing quest reward/claim rules remain unchanged.
- Menus use readable responsive type, visible focus states, 44px+ controls, bounded scrolling and focus trapping/restoration. Mobile dialogue uses a bottom sheet. UI scale options are 90/100/115/130%; text scales within bounds while control geometry stays fitted to the viewport. Reduced motion disables HUD transitions/animations. Low quality removes overlay blur.

## Compatibility and scope

Adventure Save version 1 and its IndexedDB database/key are unchanged. New fields (`uiScale`, `trackedQuest`) are localStorage settings; `abilityTrayOpen` is transient. Existing settings receive safe defaults. Opening menus pauses gameplay and clears the ability tray. Building mode survives opening the navigation drawer so its toggle can correctly enter or exit the existing mode.

No settlement, profession or outpost systems were added. Navigation exposes implemented features only. The Netlify badge shown in the user's screenshot is not generated by this repository; this change removes the game's own crowded bottom navigation.

Source reference: docs/UI_UX_SPEC.md. Actual validation and remaining limits are recorded in TESTING.md. Screenshots are generated by e2e/ui-redesign.spec.ts across phone, tablet, landscape and desktop viewports, including 130% scale.

## Compact status HUD and crisp world names

The arrows button beside Pause hides/restores the player, companion, quest and minimap status panels while keeping movement, actions and hotbar usable. The minus/plus on the tracked mission independently switches it to a 44px quest chip. These are browser preferences (`hudMinimized`, `questMinimized`), remembered across reloads. The companion ability tray still opens from the touch controls when the status HUD is hidden.

World names no longer use tiny canvas-texture sprites. `WorldLabels` anchors native 14–18px browser text to projected 3D positions, independent of WebGL resolution and camera zoom. Positions are rounded to CSS pixels, and nearby labels wrap/reposition to avoid each other and the player. The renderer bounds label count/distance, hides offscreen/menu labels, updates positions without React frame state, and removes nodes on unmount. Labels ignore pointer input so object/world interactions remain available underneath.

## Quiet play surface and mobile reference

The default quest tracker is a compact chip, with details available on demand. Map/task sections start collapsed unless the player explicitly saved their expansion. Existing browser preferences receive a one-time HUD style migration; adventure saves remain unchanged.

World names appear only for the current nearby interaction target. NPC work/rest text, distant practice-target HP labels and generic scenery names do not fill the world view. Native browser text stays sharp, and placement reserves the player and visible HUD areas. One direction arrow and distance point toward the tracked mission; it hides at the destination and while menus/dialogue are open.

Routine pickups, selections, crafting confirmations, regrowth, no-target and cooldown notices are quiet. Inventory/material counts and contextual states provide feedback. Blocked actions, save failures, major rewards and new companions still show a short, deduplicated notice. Mobile controls use four rounded, cream-edged petals with distinct attack/ability/gather/jump colours, a central sprout, and a soft joystick. Player/companion cards and the hotbar use the supplied cream-and-forest reference palette.

`PlatformBadgeGuard` handles known Netlify badge elements and injected branding links/frames, including small wrapper/shadow containers, so they do not cover the hotbar. The local browser suite injects branding deliberately to test this; it does not verify the live Netlify deployment.

Resting residents now have an explicit Knock button at their doorway. E and the mobile context button use the same action. The villager stands up, walks through the door, and begins dialogue outside once the player is nearby. Repeat knocks are disabled during the approach. Conversation pauses the world clock; afterwards the resident waits briefly and returns indoors. Door visits are transient and do not add save fields or rewards.

## Reference name plates

The supplied reference now guides overhead tags: cream rounded plates, moss-green names, soft borders/shadows, a green player status dot and companion portrait/level/health. Only the active companion is labelled continuously. Other names remain contextual; a focused enemy can show its small health bar during combat. Plates reserve HUD space and use native browser text rather than scaled textures. Portraits are original local SVGs for the existing four species.
